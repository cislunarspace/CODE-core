# 相对运动任务级工具面

e2m2e 不把 `e2m2e.algorithm.proximity` 的相对运动能力封装成任务级工具。proximity 保持算法层能力，进程内调用方直接 import 使用，CLI、MCP、GUI sidecar 不设对应工具。

## 为什么不在范围内

任务级接口服务需要快速完成任务分析的调用方，前提是存在明确、可重复的调用任务。#835 的正文列出的是算法能力清单，包括相对轨迹传播、LVLH 互转、调相脉冲与被动安全报告，没有给出调用场景、请求形状与验收条件。没有任务，就没有判断封装是否自然的依据。

算法完整度要按任务衡量，不能按模块清单衡量。相对传播的 CR3BP 链路闭合，但星历 Encke 仍是占位，调相只支持两脉冲，LVLH 参考体语义待 #834，多脉冲与参考几何在 #833。Floquet 模态已随 #832 交付，只覆盖平面周期轨道，三维模态属后续扩展。现在把这条链路冻进工具面，后续每次算法变化都要改请求响应模型与文档。

这些能力也不共享同一个任务形状。传播与分析是一类问题，调相搜索是另一类，安全校验是轨迹的后处理。合并成一个工具会引入模式切换与条件字段，拆成多个工具又缺少共同的任务驱动。

维护一个任务级工具的成本是长期的，包括请求模型、单位换算、CLI 与 MCP 的 schema、文档、回归测试、兼容承诺。当前没有重复调用场景，收益不足以覆盖成本。论文复现可以继续走进程内 import，这条路径本来就受支持。

## 复核路径

本决定由维护者裁定（#835）。定位变化时按以下路径复议：

- 触发条件是出现具体任务级消费场景，例如 GUI 或 MCP 调用方需要一次完成“给定名义轨道与初始相对状态，输出相对轨迹、LVLH 表示与被动安全报告”，并且该调用会被重复使用。
- 复议时先写任务描述，包括调用场景、输入、输出与验收，再按当时的接口规则决定归属与粒度。不要恢复 #835 的能力清单写法。
- 涉及 LVLH 参考体时至少等 #834 落地。涉及多脉冲或参考几何时等 #833 落地。Floquet 模态已随 #832 交付，只覆盖平面周期轨道，三维模态属后续扩展。
- 能力侧的相关推进见 #852 的地图单。它不改变本记录的触发条件，只影响复议时的算法成熟度判断。
- 本记录不改变 proximity 的算法层定位。专家继续经 `e2m2e.algorithm.proximity` 使用，相关测试继续保留。
