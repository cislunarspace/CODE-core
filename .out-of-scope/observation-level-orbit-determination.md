# 观测级定轨（测量模型 + 估计器）

e2m2e 不引入观测级定轨：不建测站模型（`GroundStation` / 站址表 / 站心惯性状态归算），不实现测距、测速（积分多普勒）、时延观测方程与观测偏导 H、权矩阵，也不新增批最小二乘 / EKF / CKF 估计器、SNC 过程噪声与形式协方差输出。

站保蒙特卡洛保留既有语义：三轨道结构（目标 / 真实 / 测量）配 `NavigationErrorModel` 散布注入，是项目接受的“测定轨”抽象，不升级为真测量级定轨。

## 为什么不在范围内

**定位**：#670 的能力审查（同批，维护者撰写）定调 —— “本仓库是轨道设计/预报/控制工具集，不是定轨（OD）系统”：力模型层大部分有实现机制，但观测建模与估计解算层整体缺失，论文口径的数据资产（JGM3、GL0660B、DE421）也不随仓库提供。调用方问的是“给定设计/控制目标，轨道与控制量是多少”，不是“给定跟踪数据，状态与精度是多少”。

**观测层没有独立消费者**：测量模型的服务对象是估计器（解算位置速度 6 参数、光压系数、测距系统差等）。#636 的评估把这两半作为同一个立项单元；观测层与估计器被同一次决定拒绝，不存在“只上测量模型、不上估计器”的中间形态。

**既有散布注入在定位内够用**：#636 的评估（数字与脚本见其 gist）显示，注入默认 1500 m / 2 mm/s 与文献实测精度（鹊桥在轨 1–3 mm/s）同量级；真正的差距是误差结构 —— 估计误差椭球各向异性 47.7:1（弧内最高 7810:1）、最差方向沿迹、跨历元相关 ±0.3–0.55，而注入构造上只能给各向同性白噪声。项目接受这一结构性简化：站保结论按注入 σ 的敏感性给，不承担“由跟踪条件反演精度”的问题。

**代价形态**：按 #636 的实现半径估计，真定轨意味着新增 `algorithm/od/` 模块族（测站、测量模型、跟踪调度、测量表、估计器）、新建 Rust crate 与 ABI 条目、新的数据面与生命周期 —— 是与“设计/预报/控制”并列的第二条产品线，不属本仓库范围。

**不是 bug**：不存在“应该能定轨却坏了”的行为；这是范围决定，不是失效修复。

## 复核路径

本决定由维护者裁定（#636 原话：“暂不将观测级定轨纳入 e2m2e”），拒绝依据是项目定位（见上），评估材料全数留存。定位变化时按以下任一路径复议：

- 重开 #636：评估材料、候选用例清单、三支柱量化分析、实现半径估计、ADR 草案与复现 gist（<https://gist.github.com/ouyangjiahong26/a8f8f6aea4e46d649577710af434c5d7>）均留存，Project 回 `Inbox`；
- 或按其中的 ADR 草案拆分新 issue（测站与测量模型 / 跟踪调度 / 批最小二乘 / EKF+CKF+SNC / 残差剔除与一致性统计 / `e2m2e-od` crate / 注入与估计并存模式 / 测量表数据面）。

评估中内联的约 20 行测量几何偏导与全部原始输出只存 gist，未入库；不以 nyx（AGPL-3.0）代码或其 LRO 算例输出作回归基准（ADR 0013“按定义验证”）。
