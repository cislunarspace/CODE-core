# 文档撰写技能

## 工作流程

### 1. 收集变更信息

撰写文档前，先获取最新的代码变更：

```bash
git log --oneline -10  # 查看最近10条提交
git diff HEAD~5..HEAD  # 查看最近5次提交的具体变更
```

重点关注：
- 新增的类、方法和属性
- 重大重构（类继承关系变化）
- API 签名变更
- 新增功能模块

### 2. 确定文档位置

根据变更内容选择合适的文档位置：

| 变更类型 | 文档位置 |
|---------|---------|
| 核心类变更 | `docs/core/*.md` |
| 算法实现 | `docs/algorithms/*.md` |
| 新增教程 | `docs/guides/*.md` |
| API 变更 | `docs/reference/api-reference.md` |
| 整体更新 | `docs/index.md` |

### 3. 文档结构模板

核心模块文档应包含：

```markdown
# 模块名称

**文件**: `e2m2e/module/path.py`

**类签名**:
```python
class ClassName(BaseClass):
    """类说明"""
```

## 设计原理
- 类的设计目的
- 关键算法或数学模型

## 属性

| 属性名 | 类型 | 说明 |
|--------|------|------|
| attr1 | type | 说明 |

## 核心方法

| 方法 | 说明 |
|------|------|
| method1() | 说明 |

## 使用示例
```python
# 示例代码
```
```

### 4. 编写规范

- **简洁为要**：只记录关键信息，不复制源码注释
- **中英双语**：项目使用 `_en.md` 后缀表示英文版
- **链接索引**：在 `docs/index.md` 更新模块索引
- **数学公式**：使用 LaTeX 格式（`$$...$$`）
- **表格对齐**：使用管道符表格清晰展示属性方法

### 5. 更新索引

修改任何文档后，检查 `docs/index.md` 是否需要更新：
- 新模块是否添加到索引表
- 链接是否有效
- 文档结构是否需要调整

## 快速检查清单

- [ ] 已阅读最近 5-10 条 git commit
- [ ] 新类/方法已添加到对应文档
- [ ] 文档位置符合项目结构约定
- [ ] `docs/index.md` 索引已更新（如需要）
- [ ] 中英文版本一致（如适用）
- [ ] 代码示例可执行
