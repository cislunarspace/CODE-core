# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in e2m2e, please report it responsibly.

### Preferred: GitHub Security Advisories

Go to **Security → Advisories** on our [GitHub repository](https://github.com/cislunarspace/e2m2e/security/advisories) and click "Report a new vulnerability."

This allows us to discuss the issue privately and coordinate a fix before public disclosure.

### Alternative: Email

Send a description of the vulnerability to **ouyangjiahong22@nudt.edu.cn**.

Please include:

- A description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if any)

## What Qualifies as a Security Issue

- Remote code execution
- Arbitrary file read/write
- Input validation flaws leading to crashes or memory corruption
- Dependency vulnerabilities with known CVEs
- Exposure of sensitive data through error messages or logs

## What Does NOT Qualify

- General bugs that cause incorrect computation results (report as a regular issue)
- Feature requests
- Performance issues

## Response Timeline

- **Acknowledgment**: within 48 hours
- **Initial assessment**: within 5 business days
- **Fix and disclosure**: timeline depends on severity and complexity

We appreciate responsible disclosure and will credit researchers in our security advisories.
